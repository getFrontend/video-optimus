## Веха A — Надёжность кодирования и сохранение медиа

### Цели

- Независимо проверять каждый аппаратный энкодер и использовать только реально работающие варианты.
- Расширить анализ медиа свойствами, необходимыми для корректного сохранения и проверки.
- Не терять несовместимые потоки молча; валидировать критичные характеристики результата.
- Добавить регрессионные unit-тесты для выбора кодера, анализа FFprobe и валидации.

### Выполнение

- [x] Проверка каждого аппаратного кодера теперь независима; опции энкодера считываются через `ffmpeg -h encoder=...`, неподдерживаемый quality-параметр не допускает кодер к выбору.
- [x] `VideoMetadata` содержит отдельный видеобитрейт, pixel format/bit depth, цветовые параметры, rotation, информацию об аудио/субтитрах, вложениях и data-потоках. Новые поля имеют serde defaults; проверена десериализация старых метаданных очереди.
- [x] Bitmap/сложные субтитры и вложения направляются в MKV с копированием; поддерживаемые текстовые субтитры преобразуются в `mov_text` для MP4. Data-потоки, дополнительные/вложенные изображения и несколько видеодорожек отклоняются с объяснением вместо неявной потери.
- [x] Перед публикацией проверяются количество потоков, цветовые параметры, rotation, bit depth и свойства аудиоканалов; для выбранной видеодорожки используется её фактический FFprobe stream index.
- [x] Smart/Fast/Maximum получили разные приоритеты кодеков; параметры пресета добавляются только при наличии в объявленных опциях энкодера.
- [x] Rust-тесты: 31 пройдено. Добавлены проверки выбора отдельных QSV-кодеров, пресетов режимов, безопасного контейнера/потоков, target bitrate, параметров FFmpeg, разрядности, rotation, цветовых метаданных и обратной совместимости.
- [x] `npm run build`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` проходят.
- [~] Реальную совместимость параметров конкретной FFmpeg-сборки и поведение Intel QSV проверить невозможно: FFmpeg/FFprobe и тестовые видео в окружении не найдены.

### Изменения и проверки

- Веха A завершена на уровне кода и unit-тестов. Интеграционное кодирование и проверка QSV остаются внешней проверкой на системе с FFmpeg и подходящими медиафайлами.

## Веха B — Режимы сжатия и целевой размер

### Цели

- Развести Smart, Fast и Maximum по стратегии кодека и параметрам.
- Оставить Custom недоступным, пока пользовательские параметры не будут реально подключены.
- Заменить процентную эвристику размера на оценку по длительности и битрейту.
- Реализовать ограничение размера с проверкой достигнутого результата и предупреждением о компромиссах.

### Выполнение

- [~] Основной поток кода готов; калибровка качества и фактическое попадание в размер не подтверждены на видео/FFmpeg.

### Изменения и проверки

- Режимы Smart/Fast/Maximum различаются приоритетом кодеков и параметрами пресетов. Custom остаётся отключённым до появления реальных пользовательских параметров.
- Добавлена настройка целевого размера (МБ), сохранение в параметрах приложения и копирование значения в задание очереди.
- Битрейт цели рассчитывается из длительности, размера и битрейта аудио с резервом под контейнер. x264/x265 выполняют два прохода с переходом на один проход при ошибке; остальные кодеры используют одноэтапное управление по битрейту.
- Результат проверяется относительно цели с допуском 5%; отклонение показывается в карточке результата. Невозможный размер, не оставляющий минимального видеобитрейта после резерва аудио, отклоняется.
- Прогноз диапазона теперь использует видеобитрейт/длительность и аудиобитрейт; если данных недостаточно, прогноз скрыт. Коэффициенты качества остаются ориентировочными, не калиброваны на тестовом наборе.
- Проверки: `npm run build`; Rust unit-тесты — 31 пройден; Clippy и rustfmt проходят. Реальный encode и соответствие допуску не проверены: FFmpeg/FFprobe и тестовых видео нет.

- При открытии панель настроек теперь поднимается выше sticky-навигации (`z-index: modal`), а прозрачный native radio занимает всю строку варианта и служит полноценной областью клика.
- В браузерном веб-предпросмотре меню раскрывается, все radio остаются доступными, а настройки меняются в локальном состоянии предпросмотра. Их запись на диск подтверждается только в Tauri.
- Звезда рекомендации размещена рядом с названием и в триггере, и в меню; профиль качества «Збалансована» также отмечен как вариант по умолчанию. Tooltip и accessible name сообщают «Рекомендовано за замовчуванням».
- После правок `npm run build` проходит (TypeScript и Vite production build).

## Custom — ручные настройки

- Пункт «Власний» активен и открывает поля кодека (H.264/HEVC/AV1), устройства (авто/CPU/QSV), пресета, контейнера, аудиокодека и аудиобитрейта AAC, а также ручного видеобитрейта.
- Доступность кодека и пресета привязана к данным runtime: списки используют успешно обнаруженные CPU/QSV-кодеры и их поддерживаемые опции. При Auto QSV предпочитается, при ошибке доступен CPU fallback.
- Параметры сохраняются в `AppSettings` и копируются в каждый `VideoJob`; добавлены serde defaults для старых настроек и элементов очереди. Ручной битрейт применяется, если не задан целевой размер; при наличии target size он имеет приоритет. Ручной аудиобитрейт используется только для AAC.
- Выбор MP4 отклоняется до постановки задания, если для сохранения вложений или неподдерживаемых субтитров требуется MKV.
- Проверки: свежий production preview подтвердил выбор режима Custom, смену кодека/устройства/аудиокодека и ввод видеобитрейта; `npm run build`; `cargo test --lib` — 37/37; Clippy и rustfmt проходят.
- Ограничения: в Custom пока нет изменения частоты кадров и произвольных дополнительных параметров FFmpeg. Реальное кодирование/QSV с тестовыми видео требует внешней проверки на установленной сборке FFmpeg.

## Восстановление прогноза размера в очереди

- Причина пропажи: новый расчёт скрывал карточку, если в метаданных не было битрейта видеопотока или битрейта каждой аудиодорожки. Это затрагивало в том числе сохранённые задания старого формата, у которых дополнительные поля потоков подставляются serde defaults.
- При полных метаданных прогноз по-прежнему рассчитывается из битрейтов и длительности. Когда данных недостаточно, используется резервная оценка по размеру исходника, режиму и выбранному профилю качества, чтобы карточка не исчезала.
- Подсказка к карточке различает оценку по медиапотокам и ориентир по типовым коэффициентам. Целевой размер и заданный вручную битрейт Custom продолжают иметь приоритет над этим fallback.
- Проверки: `npm run build`; отдельно проверены профильный fallback для старых метаданных, расчёт по полным метаданным и Custom с ручным битрейтом. Узкая и широкая карточки сохраняют существующие container-query стили; заполненную очередь нельзя проверить в веб-предпросмотре без Tauri и медиафайлов.

## Пересчёт прогноза при выборе настроек

- Ожидающие задания пересчитывают прогноз сразу по текущим настройкам сайдбара, включая режим, качество, Custom и целевой размер.
- Это только предпросмотр: сохранённые параметры задания не меняются. Применение выполняется отдельно для выбранных заданий через групповое действие в очереди.
- Уже обрабатываемые, завершённые и ошибочные задания продолжают показывать прогноз по своим параметрам.
- В панели настроек добавлено пояснение этого поведения. Проверки: `npm run build` и runtime-проверка прогнозов.
