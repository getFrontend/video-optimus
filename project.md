# PROJECT: VIDEO OPTIMUS
## Разработка интеллектуального локального видеокомпрессора для Windows 11

Ты — senior software engineer, специализирующийся на Rust, FFmpeg, видеокодировании, производительности Windows-приложений и разработке современных Desktop UI.

Твоя задача — спроектировать и реализовать полноценное desktop-приложение для Windows 11, предназначенное для интеллектуального сжатия и оптимизации видео с максимальным сохранением визуального качества.

Это не просто видеоконвертер и не графическая оболочка над FFmpeg.

Необходимо создать удобный, быстрый и интеллектуальный локальный видеокомпрессор, который самостоятельно анализирует исходные видео, подбирает подходящий кодек и параметры сжатия, использует аппаратное ускорение и позволяет обрабатывать множество файлов одновременно через очередь заданий.

**Главный принцип продукта: минимальный размер файла при максимально возможном сохранении исходного визуального качества.**

Необходимо реализовать работающий продукт, а не демонстрационный интерфейс или набор заглушек.

# 1. ИНФОРМАЦИЯ О ПРОЕКТЕ

Рабочее название: Video Optimus.

Целевая ОС: Windows 11 x64.

Основной язык разработки: Rust.

Архитектура приложения:
- Tauri 2 — Desktop Framework.
- Rust — Backend и основная бизнес-логика.
- React + TypeScript — пользовательский интерфейс.
- Vite — сборка Frontend.
- Tailwind CSS — оформление интерфейса.
- FFmpeg — обработка и кодирование видео.
- FFprobe — анализ исходных и итоговых файлов.

Не использовать Electron.

Не реализовывать видеокодеки самостоятельно. Использовать проверенные реализации кодирования через FFmpeg.

Приложение должно работать полностью локально, без отправки видеоматериалов на серверы и без обязательного подключения к интернету.

## 1.1. Целевое оборудование

Основная конфигурация, на которой необходимо оптимизировать и тестировать приложение:

- CPU: Intel Core Ultra 7 155H.
- CPU: 16 ядер / 22 потока.
- GPU: встроенная Intel Arc Graphics.
- Дискретная видеокарта отсутствует.
- RAM: 32 ГБ.

Основной приоритет аппаратного ускорения — Intel Quick Sync Video (QSV).

Поддержать аппаратное кодирование:
- H.264 QSV.
- HEVC QSV.
- AV1 QSV.

Однако не считать наличие процессора гарантией доступности каждого энкодера в конкретной системе. Проверять реальную поддержку посредством FFmpeg, драйверов Intel и доступных аппаратных устройств.

Предусмотреть программное кодирование через CPU:
- libx264.
- libx265.
- libsvtav1.

Конкретная доступность зависит от конфигурации сборки FFmpeg.

Архитектуру сделать расширяемой для будущей поддержки NVIDIA NVENC и AMD AMF, но не усложнять первую версию кодом для неподдерживаемого оборудования.

Пример исходного видео:
- Длительность: 13 минут.
- Разрешение: 1920×1080.
- Размер: 1,6 ГБ.

Это целевой сценарий, а не гарантия для любого видео.

- Записями онлайн-встреч.

Обычные видео с камер, динамичные сцены и игровые записи также должны поддерживаться.

# 3. ВИДЕОКОДЕКИ И ТЕХНОЛОГИИ

Реализовать поддержку трёх основных видеокодеков.

## H.264 / AVC

Назначение:
- Максимальная совместимость.
- Быстрая обработка.
- Поддержка практически всеми устройствами.

Аппаратный кодировщик: h264_qsv.

Программный кодировщик: libx264, если он включён в сборку FFmpeg.

Использовать в режиме Compatibility или когда требуется максимальная совместимость.

## H.265 / HEVC

Назначение:
- Хорошее соотношение размера и качества.
- Эффективное сжатие.
- Хорошая совместимость с современными устройствами.

Аппаратный кодировщик: hevc_qsv.

Программный кодировщик: libx265.

Использовать в Fast Compress и Smart Compress, если сравнительное тестирование подтверждает его преимущество для конкретного материала.

## AV1

Назначение:
- Высокая эффективность сжатия.
- Получение компактных видеофайлов.
- Хорошее сохранение воспринимаемого визуального качества.

Аппаратный кодировщик: av1_qsv.

Программный кодировщик: libsvtav1.

Особое внимание уделить сравнению аппаратного и программного AV1.

Не считать AV1 автоматически лучшим решением для каждого видео. Учитывать время обработки, качество, совместимость и итоговый размер.

## Система выбора кодека

Реализовать отдельный модуль CodecManager.

Он должен:
1. Обнаруживать доступные кодировщики FFmpeg.
2. Определять доступность Intel Quick Sync.
3. Проверять поддержку аппаратного AV1, HEVC и H.264.
4. Определять доступность программных кодировщиков.
5. Проверять доступные аппаратные устройства.
6. Получать информацию о возможностях конкретного энкодера.
7. Выбирать подходящий кодировщик согласно режиму работы.
8. Выполнять fallback на CPU при ошибке GPU.

Не использовать одинаковые параметры CRF, QP или Quality для разных кодеков. Для каждого кодировщика создать отдельный профиль настроек.

Перед использованием параметров проверить их доступность в установленной версии FFmpeg через информацию соответствующего энкодера.

# 4. РЕЖИМЫ СЖАТИЯ

Реализовать четыре основных режима.

## 4.1. Smart Compress — основной режим

Это режим по умолчанию.

Пользователь добавляет видео и запускает оптимизацию. Программа самостоятельно определяет подходящие настройки.

Алгоритм:
1. Анализ исходного видео.
2. Определение кодека, разрешения, FPS, битрейта и других параметров.
3. Анализ характера изображения.
4. Определение доступного аппаратного ускорения.
5. Оценка сложности видео.
6. Выбор подходящего кодека.
7. Выбор профиля качества.
8. Подготовка параметров кодирования.
9. Перекодирование.
10. Проверка итогового файла.

При выборе учитывать:
- Долю статичных сцен.
- Интенсивность движения.
- Частоту смены сцен.
- Наличие мелкого текста.
- Детализацию изображения.
- Градиенты.
- Шум и зернистость.
- Наличие динамичных анимаций.
- Исходный битрейт.

Для записей экрана уделить особое внимание сохранению читаемости мелкого текста, тонких линий, курсора и элементов интерфейсов.

Не применять агрессивные фильтры шумоподавления, размытия или изменения резкости автоматически.

Если анализ показывает, что видео уже хорошо сжато, сообщать пользователю об ограниченных возможностях дальнейшей оптимизации.

## 4.2. Fast Compress

Приоритет — скорость.

Предпочтительно использовать Intel Quick Sync.

Начальный приоритет:
- HEVC QSV.
- AV1 QSV, если тесты показывают приемлемое сочетание скорости и качества.
- H.264 QSV для максимальной совместимости.

Использовать настройки, обеспечивающие хорошее визуальное качество при минимальном времени обработки.

Не допускать чрезмерного повышения скорости за счёт заметного ухудшения изображения.

## 4.3. Maximum Compression

Приоритет — максимальная эффективность сжатия.

Использовать программное кодирование на CPU, если оно обеспечивает лучший результат.

Предпочтительные технологии:
- SVT-AV1.
- x265.

Использовать подходящие пресеты кодировщиков, ориентированные на эффективность сжатия, а не исключительно на максимальную скорость.

Для SVT-AV1 предусмотреть настройку пресета и CRF.

Учитывать, что более медленные пресеты могут существенно увеличивать продолжительность обработки.

Не допускать чрезмерной нагрузки на систему без возможности управления интенсивностью кодирования.

## 4.4. Custom

Расширенный пользовательский режим.

Позволить выбирать:
- Видеокодек.
- Аппаратное или программное кодирование.
- Профиль качества.
- Пресет скорости.
- Битрейт.
- Частоту кадров, если пользователь явно разрешил её изменение.
- Аудиокодек.
- Битрейт аудио.
- Контейнер.
- Папку сохранения.
- Дополнительные параметры, только если они безопасны и поддерживаются конкретным кодировщиком.

Не показывать пользователю технические параметры, которые не поддерживаются выбранным энкодером.

# 5. СИСТЕМА КАЧЕСТВА

Реализовать отдельную систему Quality Profiles.

Пользователь не должен обязательно разбираться в CRF, QP, GOP, VBR и других параметрах.

Предусмотреть понятные профили:

### Near Original
Максимальное сохранение визуального качества.

### High Quality
Высокое визуальное качество и разумный размер файла.

### Balanced
Оптимальный баланс размера и качества.

### Compact
Приоритет компактности при приемлемом качестве.

Пользователь выбирает понятный профиль, а приложение преобразует его в подходящие настройки конкретного кодека.

Создать отдельные калибровочные профили для:
- H.264 QSV.
- HEVC QSV.
- AV1 QSV.
- x264.
- x265.
- SVT-AV1.

Не использовать одинаковые значения параметров качества для разных энкодеров.

Настройки должны определяться на основании сравнительных тестов.

## 5.1. Автоматическое определение качества

Приложение должно анализировать исходное видео и выбирать профиль, исходя из его характеристик.

Например:

Запись презентации с неподвижными слайдами:
- Можно использовать более эффективные настройки сжатия.
- Особое внимание уделить чёткости текста.

Динамичное видео:
- Необходимо увеличить качество и сохранить детали движения.

Видео с мелким текстом:
- Не допускать размытия шрифтов.
- Сохранять чёткие границы элементов.
- Избегать чрезмерного квантования.

Видео с шумом:
- Не применять автоматическое удаление зернистости без согласия пользователя.

# 6. TARGET FILE SIZE

Реализовать отдельную функцию Target File Size.

Пользователь может задать желаемый размер выходного файла.

Примеры:
- 100 МБ.
- 200 МБ.
- 250 МБ.
- 500 МБ.
- 1 ГБ.
- Пользовательский размер.

Приложение должно:
1. Получить продолжительность исходного видео.
2. Определить размер аудиодорожек.
3. Рассчитать доступный битрейт для видео.
4. Учесть контейнер и служебные данные.
5. Выбрать поддерживаемый режим управления битрейтом.
6. Использовать двухпроходное кодирование, если оно доступно и оправдано.
7. Проверить итоговый размер.

Для кодировщиков без полноценного двухпроходного режима использовать подходящий VBR или другой поддерживаемый механизм.

Допуск по размеру должен быть настраиваемым.

По умолчанию стремиться к отклонению не более 5%, если энкодер позволяет достичь этой точности.

Если размер достигнут ценой сильного ухудшения качества, показать предупреждение.

Не обещать достижение заданного размера без потери качества.

# 7. АНАЛИЗ ИСХОДНОГО ВИДЕО

Создать VideoAnalyzer на основе FFprobe и дополнительных инструментов FFmpeg.

Определять:
- Название файла.
- Размер.
- Продолжительность.
- Разрешение.
- FPS.
- Средний FPS.
- Тип кадровой частоты: CFR или VFR.
- Видеокодек.
- Битрейт видео.
- Битность.
- Цветовое пространство.
- Цветовой диапазон.
- HDR / SDR.
- Аудиокодеки.
- Битрейт аудио.
- Частоту дискретизации.
- Количество аудиодорожек.
- Субтитры.
- Дополнительные потоки.
- Поворот и ориентацию.

Дополнительно реализовать выборочный анализ видеоряда.

Использовать несколько репрезентативных отрезков из разных частей видео, а не анализировать только первый кадр.

При анализе учитывать сложность сцены, движение и количество визуальных изменений.

Не использовать чрезмерно тяжёлый компьютерный анализ для каждого файла.

Предусмотреть два уровня:
- Quick Analysis — быстрая предварительная оценка.
- Detailed Analysis — более глубокий анализ для Smart Compress.

Результаты анализа сохранять для соответствующего задания, чтобы не повторять идентичную процедуру без необходимости.

# 8. СОХРАНЕНИЕ ИСХОДНОГО КАЧЕСТВА

Это критически важный раздел.

По умолчанию приложение должно сохранять:

- Исходное разрешение.
- Исходный FPS.
- Продолжительность.
- Соотношение сторон.
- Синхронизацию аудио и видео.
- Ориентацию изображения.
- Цветовые характеристики.
- Поддерживаемые аудиодорожки.
- Метаданные.
- Субтитры, когда это возможно в выбранном контейнере.

Не изменять автоматически:
- Разрешение.
- FPS.
- Продолжительность.
- Скорость воспроизведения.
- Ориентацию.
- Громкость.
- Цветовые параметры.

Не выполнять автоматическое масштабирование, обрезку или изменение частоты кадров.

Особое внимание уделить VFR-видео. Не превращать автоматически переменную частоту кадров в фиксированную, если пользователь не дал такого разрешения.

## Аудио

Если исходная аудиодорожка совместима с выбранным контейнером, использовать stream copy без повторного кодирования.

Если требуется перекодирование, применять качественные настройки AAC.

Сохранять исходную канальность, если она поддерживается.

Поддержать несколько аудиодорожек и корректное сопоставление потоков.

Не удалять аудио автоматически.

## HDR и цвет

Обнаруживать HDR-видео.

Не применять автоматическое преобразование HDR в SDR.

Сохранять цветовые характеристики и метаданные при поддерживаемом кодировании.

Если выбранный кодек или энкодер не может корректно сохранить HDR, показать предупреждение и предложить совместимый вариант.

## Субтитры и метаданные

Сохранять поддерживаемые потоки.

При несовместимости субтитров с MP4 предложить MKV или явно предупредить о необходимости изменения формата.

Не удалять дополнительные потоки молча.

# 9. ПАКЕТНАЯ ОБРАБОТКА И ОЧЕРЕДЬ ЗАДАНИЙ

Это одна из ключевых функциональных возможностей приложения.

Пользователь должен иметь возможность добавить сразу множество видео и отправить их на обработку.

Реализовать полноценный Queue Manager.

## 9.1. Добавление файлов

Поддержать:

- Добавление одного файла.
- Множественный выбор файлов через системный диалог.
- Drag & Drop нескольких файлов.
- Добавление видео из выбранной папки.
- Добавление нескольких папок, если это технически оправдано.

Поддерживаемые входные форматы:
- MP4.
- MKV.
- MOV.
- AVI.
- WebM.
- M4V.
- TS.
- MPG / MPEG.

Автоматически проверять возможность обработки файла.

Не добавлять неподдерживаемые или недоступные файлы в очередь без объяснения причины.

## 9.2. Список заданий

Каждое задание должно отображать:

- Миниатюру видео, если её удалось получить.
- Название файла.
- Исходный размер.
- Длительность.
- Разрешение.
- Исходный кодек.
- Выбранный режим.
- Предполагаемый размер после сжатия, если его удалось оценить.
- Статус.
- Прогресс.
- Скорость обработки.
- Оставшееся время.

## 9.3. Статусы

Использовать следующие состояния:

- Pending — ожидает обработки.
- Analyzing — анализируется.
- Preparing — подготовка параметров.
- Encoding — кодирование.
- Validating — проверка выходного файла.
- Completed — успешно обработано.
- Failed — ошибка.
- Cancelled — отменено.
- Skipped — пропущено.

Статусы должны корректно обновляться в интерфейсе.

## 9.4. Управление очередью

Реализовать:

- Запуск всей очереди.
- Остановку очереди.
- Возобновление очереди.
- Отмену текущего задания.
- Отмену всех ожидающих заданий.
- Удаление отдельных элементов.
- Очистку завершённых заданий.
- Повтор неудачного задания.
- Повтор выбранных заданий.
- Изменение порядка заданий через Drag & Drop.
- Перемещение задания вверх и вниз.
- Возможность пропустить задание.

## 9.5. Модель выполнения

По умолчанию обрабатывать видео последовательно: одновременно выполняется только одно задание.

- Экономия оперативной памяти.
- Снижение нагрузки на GPU.
- Предсказуемая скорость.
- Стабильность.
- Предотвращение конкуренции между кодировщиками.

Предусмотреть настройку количества параллельных задач, но по умолчанию оставить значение 1.

Параллельная обработка должна включаться только при осознанном выборе пользователя и учитывать доступные ресурсы.
